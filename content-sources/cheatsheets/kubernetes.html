Kubernetes_

Guía de atajos · kubectl y DevSecOps
user@dajomar:~$ kubectl get pods

Arquitectura

Control planeFunción
kube-apiserverLa puerta de entrada: todo pasa por su API.
etcdBase de datos del clúster. ⚠ Guarda los Secrets.
schedulerDecide en qué nodo corre cada pod.
controller-managerMantiene el estado deseado (réplicas, nodos).
Cada nodo
kubeletAgente que arranca y vigila los pods.
kube-proxyReglas de red para los Services.
runtimeEjecuta los contenedores (containerd).

Igual que Terraform, Kubernetes es declarativo: le dices "quiero 3 réplicas" y él se encarga de que siempre haya 3.

Objetos principales

PodUnidad mínima: uno o más contenedores juntos.
DeploymentMantiene N réplicas de un pod y hace rollouts.
StatefulSetPods con identidad y disco fijo (bases de datos).
DaemonSetUn pod en cada nodo (agentes de logs, EDR).
Job / CronJobTareas que terminan / programadas.
ServiceIP y DNS estables para un grupo de pods.
IngressEntrada HTTP/HTTPS desde fuera del clúster.
ConfigMapConfiguración no sensible.
SecretDatos sensibles (⚠ solo en base64).
NamespaceSepara recursos por equipo o entorno.
PV / PVCDisco persistente / solicitud de disco.

Contextos y namespaces

kubectl config get-contexts
kubectl config use-context prod-cluster
kubectl config current-context
kubectl get ns
kubectl config set-context --current \
  --namespace=mi-app

La config vive en ~/.kube/config. ⚠ Contiene credenciales: trátala como una contraseña.

Pro Tip: Antes de cualquier cambio corre kubectl config current-context. El error más caro de Kubernetes es borrar algo en prod creyendo que estabas en dev.

Consultar

Crear y aplicar

kubectl apply -f deploy.yaml
kubectl apply -f k8s/  # carpeta completa
kubectl diff -f deploy.yaml  # qué cambiaría
kubectl delete -f deploy.yaml
# generar YAML sin crear nada
kubectl create deployment web --image=nginx \
  --dry-run=client -o yaml > deploy.yaml

Deployments y rollouts

kubectl scale deploy web --replicas=3
kubectl set image deploy/web web=nginx:1.27
kubectl rollout status deploy/web
kubectl rollout history deploy/web
kubectl rollout undo deploy/web  # volver atrás
kubectl rollout restart deploy/web

EstadoCausa probable
PendingSin recursos en los nodos o PVC sin disco.
ImagePullBackOffImagen o tag incorrecto, o registry privado sin credenciales.
CrashLoopBackOffLa app arranca y se cae: mira logs --previous.
OOMKilledSuperó su límite de memoria.
CreateContainer ConfigErrorFalta un ConfigMap o Secret referenciado.

Deployment seguro (YAML)

apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels: { app: web }
  template:
    metadata:
      labels: { app: web }
    spec:
      automountServiceAccountToken: false
      securityContext:
        runAsNonRoot: true
        seccompProfile: { type: RuntimeDefault }
      containers:
        - name: web
          image: registry.io/web:1.4.2  # tag fijo
          ports: [{ containerPort: 8080 }]
          securityContext:
            allowPrivilegeEscalation: false
            readOnlyRootFilesystem: true
            capabilities: { drop: ["ALL"] }
          resources:
            requests: { cpu: 100m, memory: 128Mi }
            limits:   { memory: 256Mi }
          readinessProbe:
            httpGet: { path: /health, port: 8080 }

Services

ClusterIPSolo dentro del clúster (por defecto).
NodePortAbre un puerto (30000-32767) en cada nodo.
LoadBalancerBalanceador externo de la nube.
kubectl expose deploy web --port=80 \
  --target-port=8080

Dentro del clúster se llega por DNS: web.mi-app.svc.cluster.local o solo web desde el mismo namespace.

ConfigMaps y Secrets

kubectl create configmap app-cfg \
  --from-literal=LOG_LEVEL=info
kubectl create secret generic db \
  --from-literal=password='S3cr3t!'
kubectl get secret db \
  -o jsonpath='{.data.password}' | base64 -d

⚠ base64 no es cifrado. Cualquiera con permiso de leer Secrets ve las contraseñas. Activa el cifrado de etcd y usa External Secrets, Sealed Secrets o un vault.

DevSecOps: RBAC

kubectl auth can-i delete pods
kubectl auth can-i --list \
  --as=system:serviceaccount:mi-app:default
kubectl get roles,rolebindings -n mi-app
kubectl get clusterrolebindings

Role/RoleBinding dan permisos en un namespace; ClusterRole/ClusterRoleBinding, en todo el clúster. Mínimo privilegio: nada de cluster-admin para apps ni personas en el día a día.

DevSecOps: aislar y endurecer

Pod Security Admission por namespace

kubectl label ns mi-app \
  pod-security.kubernetes.io/enforce=restricted

NetworkPolicy: bloquear todo por defecto

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
  namespace: mi-app
spec:
  podSelector: {}
  policyTypes: ["Ingress", "Egress"]

Después abres solo el tráfico necesario. Requiere un CNI compatible (Calico, Cilium).
