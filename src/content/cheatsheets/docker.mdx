## Conceptos clave

| | |
|---|---|
| Imagen | Plantilla de solo lectura: el sistema base, tu app y sus dependencias. |
| Contenedor | Una imagen en ejecución, aislada y desechable. |
| Dockerfile | Receta paso a paso para construir una imagen. |
| Volumen | Almacenamiento que sobrevive al contenedor. |
| Red | Permite que los contenedores se comuniquen entre sí. |
| Registry | Repositorio de imágenes (Docker Hub, GHCR, ECR). |

<p class="small">Una imagen es como una clase y el contenedor es una instancia: de una imagen puedes levantar muchos contenedores.</p>

## Información y ayuda

```bash
docker version
docker info  # contenedores, imágenes, storage
docker <comando> --help
docker system df  # espacio usado por Docker
```

## Imágenes

Descargar y listar

```bash
docker pull nginx  # por defecto toma :latest
docker pull postgres:16-alpine
docker images
docker image ls --filter dangling=true
```

Inspeccionar

```bash
docker image inspect nginx
docker history nginx  # capas y su tamaño
```

Etiquetar, subir y borrar

```bash
docker tag miapp:latest dajomar/miapp:1.0.0
docker login
docker push dajomar/miapp:1.0.0
docker rmi nginx
docker image prune  # borra imágenes colgadas
docker image prune -a  # borra las que no se usan
```

<p class="small">Formato: <code>USUARIO/REPOSITORIO:TAG</code>. Si no pones tag, Docker asume <code>latest</code>.</p>

## Correr contenedores

```bash
docker run -d --name web -p 8080:80 nginx
docker run -it --rm ubuntu bash
docker run -d --name db \
  -e POSTGRES_PASSWORD=secreto \
  -v pgdata:/var/lib/postgresql/data \
  --restart unless-stopped \
  postgres:16-alpine
```

<CommandTable>

| Flag | Descripción |
|---|---|
| `-d` | Segundo plano (detached) |
| `-it` | Terminal interactiva |
| `--rm` | Se borra al detenerse |
| `--name` | Nombre fijo para el contenedor |
| `-p 8080:80` | Puerto **HOST : CONTENEDOR** |
| `-e VAR=valor` | Variable de entorno |
| `--env-file .env` | Variables desde un archivo |
| `-v origen:destino` | Monta un volumen o carpeta |
| `--network` | Conecta a una red |
| `--restart` | no · always · unless-stopped · on-failure |

</CommandTable>

<Callout type="tip">
Las banderas cortas se pueden combinar: <code>-d -p 80:80</code> es lo mismo que <code>-dp 80:80</code>. Y para referirte a un contenedor bastan los primeros caracteres de su ID.
</Callout>

## Gestionar contenedores

```bash
docker ps  # los que están corriendo
docker ps -a  # todos, incluso detenidos
docker stop web ; docker start web
docker restart web
docker rm web
docker rm -f web  # detiene y borra
docker rename web web-prod
```

## Logs y depuración

```bash
docker logs web
docker logs -f --tail 100 web  # seguir en vivo
docker exec -it web sh  # entrar al contenedor
docker exec web cat /etc/nginx/nginx.conf
docker inspect web  # config completa en JSON
docker inspect web \
  -f '{{.NetworkSettings.IPAddress}}'
docker stats  # CPU, RAM y red en vivo
docker top web  # procesos dentro
docker cp web:/var/log/app.log ./
```

<p class="small">Si la imagen no trae <code>bash</code> (como Alpine), usa <code>sh</code>.</p>

## Volúmenes: persistir datos

Todo lo que se escribe dentro de un contenedor se pierde al borrarlo. Los volúmenes lo evitan.

| Tipo | Uso |
|---|---|
| Named volume | Docker lo gestiona. Ideal para bases de datos. |
| Bind mount | Una carpeta de tu equipo. Ideal en desarrollo. |
| tmpfs | Solo en RAM. Datos temporales o sensibles. |

```bash
docker volume create pgdata
docker volume ls
docker volume inspect pgdata
docker volume rm pgdata
docker volume prune  # borra los que no se usan
```

Montarlos al correr

```bash
# named volume
docker run -v pgdata:/var/lib/postgresql/data \
  postgres
# bind mount (ruta absoluta del host)
docker run -v "$(pwd)":/app -w /app \
  node:20 npm test
# solo lectura
docker run \
  -v "$(pwd)"/conf:/etc/nginx/conf.d:ro nginx
```

<p class="small">En PowerShell usa <code>$&#123;PWD&#125;</code> y la comilla invertida <code>&#96;</code> para cortar líneas en lugar de <code>&#92;</code>.</p>

## Redes

**Regla de oro:** contenedores en la misma red definida por el usuario se encuentran **por nombre**, gracias al DNS interno de Docker.

| | |
|---|---|
| bridge | Por defecto. Red privada dentro del host. |
| host | Usa directamente la red del host (sin `-p`). |
| none | Sin red: aislamiento total. |

```bash
docker network create app-net
docker network ls
docker network inspect app-net
docker run -d --name db --network app-net postgres
docker run -d --name api --network app-net miapi
# api se conecta a la base usando el host "db"
docker network connect app-net web
docker network prune
```

## Dockerfile

| Instrucción | Para qué sirve |
|---|---|
| `FROM` | Imagen base |
| `WORKDIR` | Carpeta de trabajo |
| `COPY` | Copia archivos al build |
| `RUN` | Ejecuta comandos al construir |
| `ENV / ARG` | Variables de entorno / de build |
| `EXPOSE` | Documenta el puerto de la app |
| `USER` | Usuario que corre el proceso |
| `CMD` | Comando por defecto (se puede reemplazar) |
| `ENTRYPOINT` | Ejecutable fijo del contenedor |

Ejemplo: app Node.js en dos etapas

```dockerfile
# Etapa 1: construir
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Etapa 2: imagen final liviana
FROM node:20-alpine
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
USER node
EXPOSE 3000
CMD ["node", "dist/index.js"]
```

Construir

```bash
docker build -t miapp:1.0 .
docker build -f Dockerfile.prod -t miapp:prod .
docker build --no-cache -t miapp .
```

<Flag>-t</Flag> nombre y tag · <Flag>.</Flag> contexto de build (carpeta actual) · <Flag>-f</Flag> otro Dockerfile

<Callout type="tip">
Copia primero <code>package.json</code> e instala dependencias, y después el resto del código. Así Docker reutiliza la caché y el build tarda segundos en vez de minutos.
</Callout>

## Docker Compose

Define varios servicios en un solo archivo `compose.yaml`

```yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"
    env_file: .env
    depends_on:
      - db
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: secreto
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

<p class="small">Compose crea una red para el proyecto: <code>api</code> llega a la base con el host <code>db</code>.</p>

Comandos de Compose

```bash
docker compose up -d  # levanta todo
docker compose up -d --build  # reconstruye antes
docker compose ps
docker compose logs -f api
docker compose exec db psql -U postgres
docker compose restart api
docker compose down  # detiene y borra
docker compose down -v  # ⚠ también los volúmenes
docker compose config  # valida el archivo
```

## Limpieza

```bash
docker container prune  # contenedores detenidos
docker image prune -a
docker volume prune
docker network prune
docker builder prune  # caché de builds
docker system prune -a  # ⚠ casi todo
docker system prune -a --volumes  # ⚠ todo
```

## Seguridad y buenas prácticas

| | |
|---|---|
| Tags fijos | Usa `postgres:16-alpine`, no `latest`. |
| No root | Agrega `USER` en el Dockerfile. |
| .dockerignore | Excluye `.git`, `.env`, `node_modules`. |
| Secretos | Nunca en la imagen: usa `.env` o secrets. |
| Imágenes chicas | Alpine, slim o distroless + multi-stage. |
| Puertos | Publica solo lo necesario: `-p 127.0.0.1:5432:5432` |
| Escaneo | Revisa vulnerabilidades antes de desplegar. |

```bash
docker scout quickview miapp:1.0
docker scout cves miapp:1.0
docker run --read-only --cap-drop ALL miapp
```

<Callout type="tip">
Si un contenedor se cae al iniciar, revisa en orden: <code>docker ps -a</code> (¿con qué código salió?) → <code>docker logs app</code> → <code>docker inspect app</code> → prueba entrar con <code>docker run -it --entrypoint sh imagen</code>.
</Callout>
