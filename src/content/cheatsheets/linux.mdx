## Comandos Básicos

### Ayuda de un comando

```bash
man ls     # manual completo
ls --help  # ayuda rápida
tldr tar  # ejemplos prácticos (si está instalado)
```

### ¿Dónde estoy y qué hay aquí?

```bash
pwd
ls -lah  # lista larga, ocultos, tamaños legibles
```

<Flag>-l</Flag> formato largo · <Flag>-a</Flag> incluye ocultos · <Flag>-h</Flag> tamaños legibles (K, M, G)

### Moverse entre directorios

```bash
cd /var/log  # ruta absoluta
cd ..        # subir un nivel
cd ~  ó  cd  # ir al home
cd -         # volver al directorio anterior
```

### Crear, copiar, mover y borrar

```bash
mkdir -p proyectos/app/src
touch notas.txt
cp archivo.txt /tmp/
cp -r carpeta/ respaldo/  # recursivo
mv viejo.txt nuevo.txt    # mover o renombrar
rm archivo.txt
rm -r carpeta/            # ⚠ sin papelera
```

### Buscar archivos

```bash
find / -name "*.conf" 2>/dev/null
find . -type f -size +100M
find /var/log -mtime -1  # modificados último día
which nginx              # ruta de un ejecutable
```

<Callout type="tip">
**Pro Tip:**
`Tab` autocompleta · `Ctrl+R` busca en el historial · `!!` repite el último comando · `sudo !!` lo repite como root · `Ctrl+C` cancela · `Ctrl+L` limpia pantalla.
</Callout>

## Ver y procesar texto

```bash
cat archivo.txt
# q para salir, / para buscar
less /var/log/syslog
head -n 20 archivo.txt
tail -f /var/log/auth.log  # seguir el log en vivo
```

### Filtrar y contar

```bash
grep -i "error" app.log
# recursivo + nº de línea
grep -rn "password" /etc/
wc -l archivo.txt
sort datos.txt | uniq -c | sort -nr
# 1ª columna separada por :
cut -d: -f1 /etc/passwd
awk '{print $1}' access.log
sed -i 's/viejo/nuevo/g' conf.txt
```

## Pipes y redirecciones

<div class="table-wrap">

| Sintaxis | Qué hace |
| --- | --- |
| `cmd1 \| cmd2` | La salida de cmd1 entra a cmd2 |
| `>` / `>>` | Escribe / agrega la salida a un archivo |
| `2> err.log` | Redirige solo los errores |
| `&> todo.log` | Salida y errores al mismo archivo |
| `cmd1 && cmd2` | cmd2 solo corre si cmd1 tuvo éxito |
| `cmd &` | Ejecuta en segundo plano |

</div>

## Permisos y propietarios

Leer `-rwxr-x---`: tipo · **usuario** · **grupo** · **otros**

<div class="table-wrap">

| Letra | Valor | Archivo / Directorio |
| --- | --- | --- |
| r | 4 | leer / listar contenido |
| w | 2 | modificar / crear y borrar dentro |
| x | 1 | ejecutar / entrar (cd) |

</div>

```bash
chmod 755 script.sh     # rwx r-x r-x
chmod 640 secreto.conf  # rw- r-- ---
chmod u+x script.sh     # +x solo al dueño
chown david:devs archivo.txt
chown -R www-data: /var/www
```

## Usuarios y grupos

```bash
whoami ; id
sudo -i  # shell como root
sudo useradd -m -s /bin/bash ana
sudo passwd ana
# agregar a grupo (-a ¡importante!)
sudo usermod -aG sudo ana
groups ana
sudo userdel -r ana
```

<p class="small">Archivos clave: `/etc/passwd` usuarios · `/etc/shadow` hashes · `/etc/group` grupos · `/etc/sudoers` (editar con `visudo`).</p>

## Procesos y servicios

```bash
ps aux | grep nginx
top        ó   htop  # monitor en vivo
kill PID             # pide terminar (SIGTERM)
kill -9 PID          # fuerza (SIGKILL)
pkill -f nombre
```

### systemd: administrar servicios

```bash
systemctl status ssh
sudo systemctl start|stop|restart ssh
# arranca y al boot
sudo systemctl enable --now nginx
systemctl list-units --type=service --state=failed
journalctl -u nginx -f  # logs del servicio
journalctl -p err -b    # errores desde el boot
```


## Compresión

```bash
tar -czvf respaldo.tar.gz carpeta/  # crear
```

## Administración de redes

### Interfaces, IPs y rutas

```bash
ip a  # interfaces y direcciones IP
ip link set eth0 up|down
ip r  # tabla de rutas / gateway
# temporal
sudo ip addr add 192.168.1.50/24 dev eth0
hostnamectl set-hostname srv01
```

### Conectividad y diagnóstico

```bash
ping -c 4 8.8.8.8
traceroute google.com    ó   mtr google.com
dig google.com +short ; nslookup google.com
curl -I https://dajomar.com  # solo cabeceras HTTP
wget https://sitio.com/archivo.iso
```

### Puertos y conexiones

```bash
ss -tulpn           # puertos en escucha + proceso
ss -tan state established
sudo lsof -i :443   # quién usa el puerto 443
nc -zv 10.0.0.5 22  # ¿puerto abierto?
# escaneo (solo en tu red)
sudo nmap -sV 192.168.1.0/24
```

<Flag>-t</Flag> TCP · <Flag>-u</Flag> UDP · <Flag>-l</Flag> escuchando · <Flag>-p</Flag> proceso · <Flag>-n</Flag> sin resolver nombres

### Configuración persistente

```bash
nmcli device status  # NetworkManager
nmcli con show
sudo nmcli con mod "Wired 1" \
  ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 1.1.1.1 ipv4.method manual
sudo netplan apply   # Ubuntu: /etc/netplan/*.yaml
```

<p class="small">`/etc/hosts` resolución local · `/etc/resolv.conf` servidores DNS · `/etc/services` puertos conocidos.</p>

### Firewall

```bash
sudo ufw status verbose       # Ubuntu
sudo ufw allow 22/tcp ; sudo ufw enable
sudo firewall-cmd --list-all  # RHEL / Fedora
sudo firewall-cmd --add-service=http --permanent
sudo nft list ruleset  # reglas de bajo nivel
```

### Acceso remoto y transferencia

```bash
ssh usuario@10.0.0.5 -p 22
ssh-keygen -t ed25519
# login sin contraseña
ssh-copy-id usuario@10.0.0.5
scp archivo.txt usuario@host:/tmp/
rsync -avz carpeta/ usuario@host:/backup/
```

### Captura de tráfico

```bash
sudo tcpdump -i eth0 port 53
sudo tcpdump -i any host 10.0.0.5 -w captura.pcap
```

<p class="small">El `.pcap` se abre luego en Wireshark.</p>

<Callout type="tip">
**Pro Tip:**
Si no hay internet, revisa en orden: `ip a` (¿tengo IP?) → `ip r` (¿tengo gateway?) → `ping` al gateway → `ping 8.8.8.8` → `dig google.com` (¿falla el DNS?).
</Callout>

## File System: cómo está organizado

En Linux **todo es un archivo** y todo cuelga de una sola raíz `/`. No hay letras de unidad (C:, D:): los discos se **montan** en carpetas. La estructura sigue el estándar **FHS**.

<div class="table-wrap">

| Ruta | Qué contiene |
| --- | --- |
| `/` | Raíz de todo el sistema |
| `/bin` `/sbin` | Comandos esenciales (hoy enlaces a /usr/bin) |
| `/boot` | Kernel y gestor de arranque (GRUB) |
| `/dev` | Dispositivos como archivos (`/dev/sda`) |
| `/etc` | Configuración del sistema y servicios |
| `/home` | Carpetas personales de los usuarios |
| `/root` | Home del usuario root |
| `/var` | Datos variables: logs, caché, bases de datos |
| `/tmp` | Temporales (se borra al reiniciar) |
| `/usr` | Programas y librerías instalados |
| `/opt` | Software de terceros |
| `/mnt` `/media` | Puntos de montaje manuales / USB |
| `/proc` `/sys` | Virtuales: info en vivo del kernel y procesos |
| `/srv` | Datos servidos (web, FTP) |

</div>

### Tipos de file system comunes

<div class="table-wrap">

| File system | Descripción |
| --- | --- |
| ext4 | El estándar en Debian/Ubuntu. Estable, con journaling. |
| xfs | Por defecto en RHEL. Muy bueno con archivos grandes. |
| btrfs | Snapshots, compresión y subvolúmenes (Fedora, openSUSE). |
| tmpfs | Vive en RAM, desaparece al reiniciar. |
| vfat / ntfs | Compatibilidad con USB y Windows. |

</div>

<p class="small">**Journaling:** registra los cambios antes de aplicarlos para recuperarse de apagones sin corromper datos. **Inodo:** ficha con los metadatos de cada archivo (dueño, permisos, bloques); el nombre solo apunta al inodo. Puedes quedarte sin inodos aunque haya espacio (`df -i`).</p>

### Discos, particiones y montaje

```bash
lsblk -f  # discos, particiones, FS y UUID
sudo fdisk -l
sudo mkfs.ext4 /dev/sdb1  # ⚠ formatea
sudo mount /dev/sdb1 /mnt/datos
sudo umount /mnt/datos
df -hT ; df -i            # uso por FS e inodos
sudo fsck /dev/sdb1       # reparar (desmontado)
```

### Montaje automático en `/etc/fstab`

```bash
UUID=1234-abcd  /mnt/datos  ext4  defaults  0  2
```

<p class="small">Dispositivo · punto de montaje · tipo · opciones · dump · orden de fsck. Prueba con `sudo mount -a` antes de reiniciar.</p>

### Enlaces

```bash
ln -s /etc/nginx/sites-available/app \
      /etc/nginx/sites-enabled/
ln archivo.txt copia_dura.txt
```

<Flag>-s</Flag> Simbólico: acceso directo a una ruta (se rompe si se borra el original). Sin <Flag>-s</Flag>: enlace duro, otro nombre para el mismo inodo.
